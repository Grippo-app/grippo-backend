# Grippo: аудит упражнений

Результат — проверяемые находки и минимальные предложения, в которых отделены
факты каталога, биомеханические выводы, эмпирические данные и правила продукта.
Экспертная роль означает метод работы, а не реальные дипломы, опыт наблюдения
пользователя или право объявить неизвестные проценты научно точными.

Для добавления новой карточки под ключ используй
[exercise-create](../grippo-exercise-create/SKILL.md); этот skill предоставляет
ему предметные методы и роли для подготовки и проверки содержания.

## С чего начать

Прочитай [порядок аудита](references/audit-workflow.md). Установи запрошенный
scope, происхождение данных и уже принятые человеком правила. По умолчанию
содержательный аудит заканчивается анализом; создание skill или доступ к
снимку не разрешают SSH, dump, запись БД либо деплой. Существующее разрешение
человека в тех же границах не спрашивай повторно.

Полный глубокий аудит ведёт [команда из десяти специализаций](references/agent-team.md):
ведущий назначает отдельных владельцев направлений и запускает их волнами.
У процентов, переводов, сложности и оборудования есть свои ответственные;
интернет-поиск и независимый разбор совокупности исследований — отдельные этапы.
Одно узкое поле требует только относящихся к нему ролей.

Загружай только нужные материалы:

## Границы выводов

- Сначала идентифицируй именно описанный вариант. Название, похожая картинка,
  соседняя запись или статья о другом тренажёре не определяют канон.
- Сумма процентов 100 подтверждает нормировку; не точность распределения.
  EMG, %MVIC, момент сустава, физическая работа и рост мышц не взаимозаменяемы.
  Одобрение редакционной карты не превращает её в измерение.
- Роль мышцы определяется задачей и механикой варианта. Изометрия может быть
  целевой; малая доля не доказывает роль стабилизатора. Не удаляй ≤3%,
  не округляй до 5% и не усредняй карты как автоматическое «исправление».
- Технический уровень отделяй от силы, веса, RPE, повторений, подвижности и
  клинических ограничений. Нет универсального enum сложности из одной статьи.
- Отсутствие различий не доказывает эквивалентность; отсутствие данных не
  доказывает ни ошибку, ни правильность существующей записи.
- Прямая ошибка, редакционное уточнение, выбор правила и нехватка данных —
  разные результаты. Для каждого числа или изменяемого cue укажи основание.
  Не добивайся обязательных исправлений в каждой записи.
- Не диагностируй по каталогу и не приписывай движению доказанную опасность
  без соответствующих данных. Для персонального/клинического запроса отдельно
  установи контекст; не превращай общий аудит в лечение пользователя.

## Инструменты и завершение

Локальный проверяющий скрипт читает явно переданный JSON, не подключает БД:

```bash
python3 .agents/skills/grippo-exercise-audit/scripts/inspect_snapshot.py /absolute/path/catalog.json
```

Его результат — структурная проверка, не биомеханический вердикт. Не запускай
AppModule, synchronize или операционные скрипты для проверки содержимого.

Для формата/потребителей нужны актуальные
[domain-data](../grippo-domain-data/SKILL.md), для языкового контракта —
[identity-api](../grippo-identity-api/SKILL.md). Разрешённое применение передавай
через [operations](../grippo-operations/SKILL.md) и действующие gates проекта;
этот skill не содержит альтернативного пути записи или восстановления.

Заканчивай реестром проверенных ID и явных пропусков, обоснованными
«было → стало», перечнем решений человека и ограничениями. Для существенного
аудита другой reviewer проверяет сырые основания, а не только итог автора.
