# Команда аудита упражнений

Полный глубокий аудит выполняет команда с отдельными владельцами направлений.
Роли задают специализацию и ответственность; они не создают лицензии, новые
факты или отдельную sandbox. Модель и разрешения наследуются от сессии.

| Профиль | Владеет решением и возвращает |
|---|---|
| [grippo-exercise-auditor](../../../../.codex/agents/grippo-exercise-auditor.toml) | План всей команды, snapshot/UUID manifest, распределение направлений, зависимости, coverage и общий реестр before→after. |
| [grippo-strength-coach](../../../../.codex/agents/grippo-strength-coach.toml) | Исполнимый канон: setup, последовательность движения, ROM/cues, что именно предлагается выполнять. |
| [grippo-biomechanics-scientist](../../../../.codex/agents/grippo-biomechanics-scientist.toml) | Механика варианта, сопротивление, действия суставов, динамические/изометрические роли и границы количественных выводов. |
| [grippo-muscle-map-specialist](../../../../.codex/agents/grippo-muscle-map-specialist.toml) | Состав целевых групп, семантика процентов, полный численный вектор и основание каждого изменения либо отсутствия after. |

## Полный каталог и узкая задача

Для полного глубокого аудита ведущий назначает **отдельного исполнителя**
каждому предметному направлению выше и итогового reviewer. Не объединяй всё
в один ответ ведущего с перечислением ролей. Если агент/данные недоступны,
покажи конкретный пробел и выполни доступные части. Нельзя объявить направление
проверенным только потому, что его роль упомянута в плане.

Для одного термина, поля или семейства назначай относящихся специалистов:
перевод — localization с coach при споре о каноне; проценты — muscle-map с
biomechanics; сложность — difficulty; машина — equipment. Спорные эмпирические
утверждения проходят researcher и evidence-analyst. Не требуй статьи для
арифметики по принятой редакционной модели или очевидного неверного перевода.
Существенные итоги проверяет другой reviewer.

## Работа волнами и зависимости

Лимит одновременных агентов не уменьшает состав команды: используй волны,
ожидая готовности зависимых материалов. Например, при трёх рабочих слотах
помимо ведущего:

1. Coach и equipment фиксируют вариант/конфликты; researcher параллельно
   ищет литературу по сформулированным вопросам и отмечает неизвестную геометрию.
2. Biomechanics разбирает установленный канон; difficulty оценивает требования;
   evidence-analyst независимо проверяет найденные исследования. Противоречие
   канона возвращается владельцам, а не выбирается голосованием.
3. Muscle-map получает канон/механику/принятую политику/синтез; localization
   получает стабильный смысл и готовит тексты языков. Параллельные черновики
   явно provisional: они не финализируются на устаревшем каноне.
4. Ведущий сводит реестр. Reviewer получает сырые данные, принятые правила,
   результаты всех направлений и сам перепроверяет существенные основания.

Это пример расписания, не обязательное количество раундов. Исследовательский
поиск можно разделить между независимыми researchers по семействам или
конкурирующим объяснениям; каждый получает свой вопрос и общий source ledger.
Синтез не считается независимым, если его автор лишь пересказал вывод researcher.
Порядок, критерий достаточности и разделение источников —
[research program](research-program.md).

## Матрица ответственности и передача

Для каждого UUID × scoped направление запиши owner, status
`pending/provisional/reviewed/not_applicable`, исходный material hash/версию
канона, выходной артефакт и причину пропуска. Смена канона/политики помечает
зависимые after как требующие перепроверки. Структурное покрытие отдельно от
содержательного; исследование семейства не подтверждает все его записи без
проверки совпадения вариантов.

Передавай исходный запрос/ограничения, UUID/поля/языки, сырой scoped материал
с provenance, принятые правила и точный вопрос. У общего поля/артефакта один
writer: coach владеет смыслом base-техники, localization — её языковой редакцией;
ведущий согласует пересечение до объединения. Проценты не меняются переводчиком,
уровень — researcher, история/таксономия — любым из них без отдельного scope.
Напомни, что другие авторы работают параллельно и их изменения сохраняются.

Каждый возвращает конкретные before→after/условия, источник решения, confidence
с причиной, неизвестное и проверки для следующего владельца:
[specialist handoffs](specialist-handoffs.md). Evidence-analyst и итоговый
reviewer не являются авторами проверяемого вывода. Разногласия сохраняются,
пока их не разрешит свидетельство, уточнение канона или решение человека.

Код, API/fallback, SQL constraints и разрешённая запись остаются у domain/
identity/operations специалистов. Localization владеет содержанием переводов,
а identity — их API контрактом. Экспертная команда сама не выполняет операции.

## Доступность и оценка

Профили лежат в project `.codex/agents/`. Если custom name недоступен текущему
инструменту, назначь отдельного доступного агента с дословным текстом профиля
и тем же scope. Это исполнение инструкций, не доказательство native activation;
глобальную конфигурацию или модель для обхода не меняй. Формат профилей —
[официальная документация](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Для проверки комплекта ответы фиксируют до показа ключа:
[behavioral evaluation](behavioral-evaluation.md). Не подменяй настоящую работу
команды одним саморевью или утверждением, что её инструкции безошибочны.
