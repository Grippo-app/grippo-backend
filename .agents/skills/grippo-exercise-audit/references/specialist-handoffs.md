# Контракты предметных специалистов

Читай раздел своей ответственности. Общие статусы, evidence и формат находки
определены в [findings-and-review](findings-and-review.md); здесь — границы
полей и данные, без которых коллега не может завершить зависимую работу.
Это аналитические выходы; они не разрешают запись в каталог.

## Мышцы и проценты

Вход: UUID, фиксированный вариант/версия канона, полный исходный bundleRefs
с ID словаря, разбор ролей biomechanics, принятая семантика процентов и
claim-level синтез исследований, если нужен эмпирический вывод.

Владелец muscle-map:

- Разделяет состав карты и численный бюджет. Проверяет пропуски, неверное
  отнесение группы, целевую изометрию, сопутствующую стабилизацию/хват и
  соответствие детализации словаря фактическим данным.
- Сначала указывает, что считают проценты: принятое распределение условных
  целевых единиц либо неизвестная модель. Числа EMG/сил/роста не объявляет
  долями этого бюджета. Исследование другой головки не создаёт новый enum.
- Возвращает полный before/after-вектор и дельту каждой строки, сумму и
  основание каждого добавления/удаления/числа. Для принятого детерминированного
  правила показывает знаменатель, расчёт и округление; выполняет его без
  нового согласования той же политики. Отсутствие мышцы в редакционной карте
  не означает физиологический ноль.
- Если роли можно уточнить, но точные числа не обоснованы, даёт качественное
  исправление отдельно, after чисел оставляет null/retain с причиной и
  конкретными альтернативами решения. Не выдаёт сохранение за валидацию.

Недопустимы автоматическое удаление ≤3%, округление всех карт до5%, одинаковые
карты только по похожему имени, среднее голосов экспертов, скрытая смена
таксономии/исторических метрик. Согласование соседних записей допустимо после
проверки одинаковой модели и канона, без заявления научной точности.

## Локализация

Вход: UUID, raw base и целевые локали с table/row/column и null/missing, принятый канон,
описанные конфликты и публичный fallback отдельно от storage. Если исходный
английский текст ошибочен, он не становится эталоном для перевода.

Владелец localization сопоставляет анатомические структуры, направление и
фазу движения, сторону тела, опоры, хват/стойку, помощь, ROM, оборудование,
единицы и модальность: «можно»/«нужно», рекомендация/обещание. Проверяет
название вместе с инструкцией: красивый текст другого варианта неэквивалентен.

Целевые локали возьми из текущего SUPPORTED_LANGUAGES и scoped raw данных;
явно ограниченный пользователем языковой scope сохраняй. Полный аудит покрывает
en/ua/ru/pt-BR/pt-PT; обе PT проверяются отдельно, с собственной терминологией.

Выход — матрица base и целевых локалей с reviewed/pending/not_applicable, терминологические
решения и минимальные before→after по конкретным сохранённым ячейкам.
Правильный перевод может сохранять естественный порядок слов; буквальное
совпадение не цель. `ua` остаётся API-кодом проекта, украинский текст —
украинским; новые locale/enums не вводятся.

Missing export не равен SQLnull; rawNULL при разрешённом fallback не является
обязательным дефектом. Не заполняй отсутствующий перевод под видом исправления
смысла без соответствующего scope. Спор о каноне передаётся coach/equipment;
неоднозначные языковые варианты показываются с основанием. При конфликте
base и локалей нельзя молча выбрать большинство. Base wording согласуется
с coach: одна итоговая редакция, без конкурирующих writers одного поля.

## Сложность

Вход: фиксированный вариант, experience и происхождение уровня, принятая
рубрика и сопоставимые anchors; физическая нагрузка/готовность — отдельные
данные. Отсутствующая рубрика является вопросом продукта, а не приглашением
создать универсальную научную шкалу.

Владелец difficulty оценивает установку, число согласованных действий,
баланс/опоры, траекторию, переходы и требования освоения при управляемой
нагрузке по [exercise model](exercise-model.md). Объясняет решающие различия
с соседним уровнем. Если принятой рубрики и канона достаточно — даёт точный
after; не блокирует редакционную классификацию требованием отдельного RCT.
Если случай пограничный — конкретно называет, какого наблюдения/решения не
хватает. Вес, RPE, повторы, сила/подвижность человека не заменяют technical enum.

Не упрощает упражнение для нужной метки, не заменяет unassisted на assisted,
не даёт персональный допуск и не переписывает нагрузку/описание/карту вне scope.
Изменение рубрики требует проверки затронутых потребителей и отдельного выбора
владельца; не распространяется молча на весь каталог.

## Оборудование и компоненты

Вход: raw equipmentRefs/components, словари, описанный setup, фактически
просмотренные медиа/документация конкретной машины, если доступны. Название
модели не доказывает геометрию, а URL — просмотр.

Владелец equipment отличает обязательную совместную комплектацию, альтернативы,
опоры, прикреплённые рукояти, способ сопротивления и разрешённые варианты помощи.
Плоский список refs сам по себе не кодирует AND/OR: если смысл альтернатив не
установлен, нельзя удалять одну или требовать всё одновременно. Для машины
важны опоры/ось/траектория/линия сопротивления, а не только торговое имя.

Компоненты проверяются по [catalog policies](catalog-policies.md) и текущему
контракту domain-data: false — присутствующая optional ветвь; null — отсутствие.
Не удаляй optional assist/extra как «выключенный» инвентарь. Body multiplier,
external input и weight_type — разные сущности, не создавай новую связь между
ними из названия. Пустой equipment list может быть валиден.

Выход: минимальные изменения конкретных refs/components либо retain/условия,
что обязательно/альтернативно/неизвестно и на чём основано, влияние на описание,
клиента и сохранённые метрики. Новая таксономия, объединение записей, API change
и пересчёт истории не входят в эту роль без отдельного запроса.

## Сведение исследовательских результатов

Researcher передаёт открытые primary sources и search log, не только вывод;
evidence-analyst возвращает независимый claim synthesis по
[research program](research-program.md). Muscle-map, difficulty и localization
получают поддержанный тезис с пределами переноса; никто не превращает
совокупность статей в точный after, которого эти данные/принятая политика не дают.
Reviewer проверяет и изменённые ячейки, и покрытие направлений «без находок».
