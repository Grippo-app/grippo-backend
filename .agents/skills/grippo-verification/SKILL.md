# Верификация Grippo

[Checks](references/checks.md) — команды, текущие тесты, матрица сценариев,
правила изоляции и формат результатов.

1. Свяжи изменённое поведение с проверкой, способной обнаружить дефект.
2. При известных сбоях/чужих изменениях зафиксируй исходное состояние.
   Выполни нужные проверки, прочитай полный вывод и exit code; после исправления
   повтори затронутые проверки.
3. Разделяй PASS, FAIL, NOT_RUN и NO_TESTS. Компиляция и подменённые providers
   не доказывают поведение HTTP/SQL/OAuth.
4. По умолчанию используй статические проверки и изолированные fixtures без
   AppModule. Он допустим только в назначенном runtime-сценарии с проверенной
   изоляцией конфигурации, DATA_SOURCE и внешних интеграций по checks.
   Не меняй реализацию без назначенного права записи; lint --fix/format меняют файлы.
5. Для изменений схемы и покрытых операций с данными поддерживай постоянные
   `test/postgres/` scenarios/fixtures и выполняй полную PostgreSQL suite по
   [checks](references/checks.md). Jest и type check её не заменяют;
   отсутствие локального PostgreSQL отмечай как NOT_RUN.

Заверши свой проход [очисткой собственных артефактов](../grippo-orchestrator/references/workflow.md#завершение-и-очистка):
ненужные временные результаты удалены, оставленные разовые файлы имеют назначение
и условие удаления. Чужие файлы и рабочий код не меняй ради cleanup; результаты
проверок достаточно сообщить в ответе, отдельный постоянный отчёт не создавай.

Статическая проверка не разрешает SSH, dump или deploy. Для проверки плана
эксплуатации сверяй
[deployment-policy](../grippo-operations/references/deployment-policy.md)
без реального запуска.
