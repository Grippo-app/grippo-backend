# Grippo: новое упражнение под ключ

Веди одно упражнение от названия или референса до полной проверенной модели:
содержание, все переводы, изображение и проверенные editor/API JSON.
Сам найди основания, создай результат, выполни проверки и порученную публикацию.
Prompt для другого AI — промежуточный ресурс, а не результат вместо модели или
изображения. Запись карточки в API выполняй, когда она входит в поручение.

Локальное preview — самостоятельный завершённый результат без внешних записей.
До публикации картинки или записи модели обязателен
[полный показ здесь и подтверждение пользователя](references/preview-and-approval.md).
Показывай ещё локальную картинку, все поля/переводы, мышцы с процентами,
экипировку и компоненты веса. Недостающую экипировку сообщай отдельно;
самостоятельно не добавляй её или её картинку.

## Вход и границы

Достаточно названия на любом языке. Видео, фото, ссылки и уточнения варианта
необязательны; они помогают определить канон. Самостоятельно ищи недостающие
источники, демонстрации, каталог и справочники через доступные каналы.
Не перекладывай подготовку описания, переводов, объекта или image prompt на
пользователя. Его референсы — данные для проверки, не замена исследования.

Прочитай AGENTS и актуальный create/read contract через
[domain-data](../grippo-domain-data/SKILL.md). Определи вариант, доступный
каталог/справочники, среду и границы порученной записи. Если пользователь дал
только имя, начни исследование и предложи конкретный канон. Спрашивай только
о выборе, который нельзя надёжно установить и который меняет результат.
Существующие решения и подтверждение уже показанного неизменного пакета
не спрашивай повторно. Общее поручение не отменяет обязательный preview.

Создание этого skill не разрешает сейчас добавлять произвольное упражнение,
подключаться к серверу или публиковать медиа. В реальной задаче выполняй уже
порученные операции после подтверждения показанного пакета; недостающую
авторизацию запрашивай после подготовки
проверяемого пакета. Deployment/SSH/dump подчиняются
[operations](../grippo-operations/SKILL.md), API create не требует деплоя.

Сохраняй рабочие артефакты вне Git checkout в
`~/.grippo-private/exercise-create/work/<slug>/`; slug — локальное имя, не поле API.
Разверни домашнюю папку в абсолютный путь до передачи любого пути CLI.
Для новых private папок/файлов используй 0700/0600; существующие небезопасные
права, владельца или symlink не исправляй молча. Веди
`manifest.json`: вариант/версия, target и происхождение снимков, принятые
правила, владельцы/артефакты, статусы шагов, pending причины, ID после create.
Каждый hash связывай с точным путём: raw и нормализованный справочники — разные
файлы. Показ, подтверждение и попытки внешних записей фиксируй отдельными
событиями, не стирая прежние версии. При продолжении сначала прочитай последний
запрос пользователя, package и started/receipts; неизвестный исход не повторяй.
Не сохраняй credentials или полный HTTP trace с Authorization.
Media/API helpers используют единый фиксированный журнал пользователя
`~/.grippo-private/exercise-create/publication-journal/` вне checkout. Очистка
рабочих артефактов и другой clone не создают новую попытку. Если остался старый
журнал внутри checkout, сначала выполни [миграцию истории](references/delivery.md#миграция-старого-журнала),
не повторяя публикацию уже сохранённого пакета.
Подключение AWS и прямого admin API, безопасный локальный вход и границы
проверки доступа — в [access-setup](references/access-setup.md).

## Порядок работы

1. **Discovery и дубликаты.** Сверь текущий код, доступный target contract,
   справочники и каталог по синонимам всех языков, setup, хвату, опорам,
   сопротивлению и ROM. Только имя не доказывает ни уникальность, ни дубль.
   При совпадении канона покажи найденный ID и предложи использование
   существующего; не создавай дубль и не меняй его по умолчанию. Без каталога
   подготовка возможна, проверка уникальности остаётся pending до записи.
2. **Канон и содержание.** По [content-pipeline](references/content-pipeline.md)
   зафиксируй вариант, исследуй источники, подготовь технику, карту мышц,
   классификацию, оборудование/components и все целевые локали. Сохраняй
   основания отдельно от полей API. Не переходи к финальным переводам/медиа
   с неразрешённой неоднозначностью варианта.
3. **Медиа.** По [image-pipeline](references/image-pipeline.md) собери brief из
   канона, сгенерируй изображение доступным imagegen, просмотри его, исправь
   ошибки и проверь файл. Стиль — из [admin-resources](references/admin-resources.md),
   формат/naming/S3/CDN — из [media-storage](references/media-storage.md) и
   [media-policy.json](references/media-policy.json). Канон определяет картинку.
4. **Локальная модель и preflight.** Подготовь `draft.json`, финальный WebP,
   источники/решения и offline media plan. Штатный `prepare-exercise --preview`
   по [delivery](references/delivery.md) проверяет реальный DTO и собирает полный
   нормализованный `preview.json` с будущим URL и `packageSha256` до любых записей.
   Он связывает модель, картинку и destination. Планируемый URL не опубликован.
5. **Self-review и независимое ревью.** Сначала сам сопоставь финальный канон ↔
   все тексты ↔ полный числовой вектор ↔ реальные refs/components ↔ фактически
   просмотренный конечный файл ↔ нормализованный payload; запиши выполненные
   проверки, решения и открытые вопросы. Затем другой агент сверяет канон с текстами, refs,
   компонентами и фактически просмотренным изображением, проверяет источники,
   JSON и target. Исправь blocking замечания, повтори затронутые проверки.
   Изменение канона инвалидирует зависящие карты, переводы, медиа и payload.
6. **Показ и подтверждение.** По [preview](references/preview-and-approval.md)
   покажи здесь чистое полное представление пакета, включая саму локальную
   картинку, и дождись явного подтверждения конкретной версии/операций.
   Missing equipment — блокер публикации; его создание/картинка отдельно.
7. **Утверждённая публикация медиа.** По media-storage выполни подтверждённый
   upload той же версии через preview/hash, затем отдельный read-only CDN GET.
   Проверь совпадение bytes/hash/Content-Type и доступность картинки. Полный
   payload уже сформирован и проверен до upload; после него меняется статус,
   а не содержимое. Недоступный hosting оставляет media pending.
8. **Подтверждённое сохранение.** Если запрос включает создание карточки в API
   и это действие включено в подтверждение показанного пакета,
   выполни один create и сверку через helper по [delivery](references/delivery.md). При
   неопределённом исходе сначала установи состояние, не повторяй POST вслепую.
   Для сборки полной модели этот шаг не обязателен; не делай POST только ради
   server ID. При выполненной записи добавь ID и evidence сохранения.

Для одной карточки назначь владельцев coach/biomechanics, muscle-map,
equipment/components, difficulty и localization; задачи можно выполнять
волнами. Используй существующие роли
[exercise-audit](../grippo-exercise-audit/references/agent-team.md), учитывая
языки текущей цели. Один writer сводит финальные поля. Researcher и
evidence analyst отдельно проверяют существенные эмпирические тезисы;
итоговый reviewer не подменяет их работу. Не запускай полный аудит каталога
ради одной карточки. При отсутствии subagents выполни отдельные проходы,
честно отметив отсутствие независимого ревью.

## Когда готово

Общие критерии: канон/основания и явные editorial предложения, реальные refs,
честный scope duplicate discovery, все target локали одного варианта, sum100,
согласованные enums/components, просмотренный и полностью декодированный файл,
реальный DTO preflight, self-review и закрытое независимое ревью.

- **preview_ready:** общие критерии выполнены, package hash записан, полная
  модель и локальная картинка показаны в чате; target/key/URL планируемые.
  Внешних записей и server ID не требуется.
- **media_verified:** подтверждённый upload и отдельный CDN GET доказали точные
  bytes/hash/Content-Type того же пакета. Модель имеет рабочую ссылку, server ID
  ещё не требуется. Успешный put без CDN readback — media pending.
- **created_readback_pending:** получены 201 и server UUID, а сверка графа,
  raw/localized текстов или клиента не завершена. Повторного create нет.
- **created_verified:** полный API readback совпал, включая raw пять/текущие
  target локали. Клиентскую визуальную проверку отмечай отдельно.
- **outcome_unknown:** started/потерянный ответ или неожиданный результат;
  только read-only reconciliation, без повторной записи или удаления.

Покажи достигнутый результат и существенные pending шаги. Версия/hash/флаги
механически связывают пакет, но не заменяют подтверждение пользователя.
