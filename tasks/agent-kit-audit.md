# Аудит skills и агентов Grippo Backend

Комплект: 7 skills, 22 справочника, UI metadata и 8 профилей агентов.
Проверены AGENTS/CLAUDE/README и валидатор; source map охватывает
124 файла исходников, конфигурации и скриптов. Факты сверены с кодом
и установленными зависимостями.

## Итоговые правила

- Общие правила находятся в AGENTS, подробности — в профильных справочниках.
  CLAUDE направляет к ним; дублирующие планы, отчёты и устаревшие рецепты удалены.
- Автор выполняет самопроверку; другой reviewer проверяет diff и исправления.
  Объём ревью и ограничения результата указываются явно.
- Каждая попытка deploy требует прямого разрешения человека и нового успешного
  `scripts/dump.sh` с проверенным источником, артефактами и защищённой копией.
  Dump-only заканчивается отчётом; автоматический повтор запрещён.
- Неизвестный исход записи требует диагностики. Повтор оценивается по всей
  операции; подтверждённый полный rollback отличается от потерянного ответа.
- Совместимость проверяется как старый клиент → новый backend. Недоступный
  consumer не объявляется проверенным.
- После паузы сверяются цель, diff, проверки и исполнители. Новые ограничения
  передаются всем; неизменившаяся авторизация сохраняется.
- Свой вклад отделяется от исходных staged/unstaged/untracked изменений.
  Коммит задачи не должен включать чужие hunks.

## Последние семь улучшений

1. Verifier допускает AppModule только в назначенном сценарии с проверенной
   изоляцией конфигурации/DATA_SOURCE/внешних providers до import/bootstrap.
   Для обычных fixtures предпочтителен отдельный тестовый module.
2. Implementer проверяет источник и условие дефекта, исправляет применимое
   в назначенных границах без повторного согласования каждого исправления.
3. Профильный специалист выбирается для предметного решения; implementer —
   для небольшого среза с определённым контрактом. У общего файла один автор.
4. Identity skill отделяет порядок исследования от выполнения HTTP:
   guards выполняются до pipes/DTO/controller. Есть ссылка на общую архитектуру.
5. Постоянная deployment policy больше не ссылается на «текущий запрос».
6. Общий routing содержит 20 запросов для независимой проверки решений,
   включая retry, Git, resume, AppModule и эксплуатационные разрешения.
7. Упрощены все 7 entrypoints, 8 профилей и общие workflow/review/checks.
   Технические имена, обязанности и обязательные ограничения сохранены.

## Исправленные фактические неточности предыдущих раундов

| Область | Уточнение |
|---|---|
| Структура комплекта | Валидатор выявляет отсутствующие/незарегистрированные роли и skills; чужая обратная ссылка не делает orphan reference доступным |
| DTO | Localized fields/components допускают отдельные массивы; отсутствие components проходит DTO и отклоняется сервисом |
| TypeORM | Уточнены nullable/unique ownership FK и null→NaN при numeric hydration |
| JWT | Missing/empty refresh secret использует fallback установленного JwtService на access secret |
| SQL | Удалён parser по префиксам строк, способный раскрыть multiline INSERT под видом DDL |
| Backup | Latest, symlinks, parents, storage и collision проверяются до dump; защищена передача partial copy |
| Deployment | Явно отделены правила пользователя от реального поведения scripts, которое их технически не обеспечивает |

Это исправления описания; перечисленные дефекты backend и scripts не объявлены
исправленными в production.

## Самопроверка и независимое ревью

Предметные области domain/identity и operations прошли перекрёстное ревью.
Governance, роли и валидатор проверены отдельным reviewer. Применимые замечания
возвращались авторам, исправлялись и повторно проверялись.

Последний раунд: авторы проверили свои diff относительно исходной копии;
независимый reviewer прочитал все 20 изменённых файлов инструкций. Другой агент
проверил 20 решений, включая выбор роли и исправление дефекта; все случаи
сохранены в общем routing.
По его замечаниям уточнены границы mocked HTTP и изолированного shell harness,
добавлены случаи неизвестного fingerprint и уже разрешённой первой попытки deploy.
Эти четыре уточнения повторно проверены обоими участниками.
Итог — APPROVE, открытых применимых замечаний нет. Это не разрешение на деплой.

## Проверки

- PASS: `python3 scripts/validate-agent-kit.py` — 7 skills, 8 agents,
  560 local links и полный inventory 124 файлов.
- PASS: scoped `git diff HEAD --check`; отдельно проверены новые файлы,
  Markdown tables/fences/EOF и поля/имена всех 8 TOML profiles.
- PASS: `bash -n` для 9 shell-примеров и 4 действующих scripts.
  Проверялся синтаксис, scripts не выполнялись.
- PASS: хеши 118 исходных файлов кода/конфигурации/scripts совпадают с исходным
  состоянием последнего раунда. Логическое staged-состояние по
  `git ls-files --stage -z` сохранено; байтовая неизменность Git stat-cache не утверждается.
- В предыдущих раундах прошли 12 негативных fixtures валидатора, проверки
  10 и затем 7 решений, synthetic DTO/TypeORM/JWT fixtures без подключения к БД.
  Это сохранённые результаты; они не выдаются за повторный запуск в последнем раунде.
- NOT_RUN: skill-creator quick_validate.py — отсутствует Python-модуль yaml.
  Packages не устанавливались; проектный валидатор успешно проверил metadata,
  ссылки и inventory.

## Ограничения

В последнем раунде изменены только инструкции и этот отчёт. Приложение,
Jest suite, TypeScript compilation, SSH, Docker и dump/deploy/restore/cleanup
не запускались; SQL payload не читался. Профили не проверялись на активацию
в каждом клиенте. Реальные remote path/fingerprint, DB identity, restore
и mobile compatibility остаются неподтверждёнными до соответствующих проверок.

Правила не добавляют operation key/дедупликацию в create API, технические
approval/backup guards в scripts или универсальную команду отделения смешанных
Git hunks. Пользовательские untracked files и сторонние source/spec changes сохранены.

## Проверка перед публикацией

По запросу на push всех изменений отдельно проверен уже существовавший diff
пяти source/spec файлов: DTO каталога, два набора тестов, HTTP logging и
предупреждения OAuth. Независимый source review — APPROVE, применимых P1/P2 нет.

- PASS: TypeScript через noEmit без incremental, exit 0.
- PASS: Jest discovery — 2 specs; полный запуск — 2 suites, 86 tests.
  HTTP fixture потребовал разрешения на временный loopback port после sandbox
  EPERM; AppModule, БД и настоящие OAuth providers не подключались.
- PASS: валидатор комплекта, diff whitespace и Bash syntax.
- Проверены 54 файла публикации на типовые признаки credentials/private keys.
  SQL dump и оба .DS_Store исключены; они остаются локальными файлами.

Эти тесты не подтверждают реальную авторизацию, persistence или production state.
Изменение логирования не означает очистку всех логов/HTTP-ответов backend.
SSH, dump/deploy/restore/cleanup не выполнялись.
